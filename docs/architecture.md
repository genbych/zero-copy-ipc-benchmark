# Архитектурное обоснование прототипа (Sprint 0)

## 1. Зачем создается этот прототип
Стандартный Linux при передаче сообщений между программами тратит лишние ресурсы процессора: ядро копирует данные сначала из программы в себя, а затем из себя во вторую программу. 

Цель нашего прототипа — создать минимальное тестовое ядро на языке Rust и на аппаратных тактах процессора доказать, что передача данных без промежуточного копирования (Zero-Copy) работает в разы быстрее стандартных сокетов Linux.

---

## 2. Ключевые решения

### Минимальное ядро
Мы не пишем огромную операционную систему с нуля. В ядре остается только критическая база: запуск процессора, разделение памяти и переключение между двумя программами. Сами тестовые программы изолированы в безопасном пользовательском режиме (Ring 3).

### Zero-Copy через Shared Buffer
Программы общаются через общий защищенный участок оперативной памяти (Shared Buffer). Ядро не читает и не перекладывает эти байты — оно лишь передает ход от одной программы к другой.

### Отказ от лишних компонентов
Для чистоты эксперимента из первой версии полностью исключены:
* Драйверы периферии и файловая система.
* Сложный планировщик задач (программы передают ход друг другу строго по очереди).
* Совместимость с POSIX (мы проверяем скорость архитектуры, а не запускаем готовые сторонние утилиты).

---

## 3. Критерий успеха
Успехом спринта считается завершение 1 000 000 циклов передачи 64-байтного сообщения между процессами в QEMU и фиксация кратного превосходства по тактам процессора над механизмом AF_UNIX в Linux.
